# 恋人を追加する

## Supabaseへの反映

ポイント機能（010）まで追加済みのプロジェクトに適用します。

1. `supabase/migrations/202609280011_lovers.sql` の全文をコピーします。
2. Supabaseの **SQL Editor → New** に貼り付け、**Run** を押します。
3. **Success. No rows returned** が出たら、全員がゲーム画面を再読み込みします。

部屋・参加者・累計ポイントを消す必要はありません。同じSQLを再実行してもデータをリセットしません。すでに進行中の試合の役職は変わりません。SQL適用前は恋人の選択肢を表示せず、従来の配役で遊べます。

## 恋人を入れる操作

待機室の **今夜のルール → 設定を変更 → 配役を自分で決める** を選びます。恋人を **2人** にして、その分ほかの役職を減らし、合計を参加人数に合わせて保存してください。

例：7人なら村人1・人狼1・占い師1・霊媒師1・騎士1・恋人2で遊べます。標準配役は変更せず、恋人は0人です。恋人の勝利点は初期5点で、主催者が0〜10点に変更できます。

## ルール

- 恋人は独立した村側の役職で、0人か2人だけを設定できます。ほかの役職とは兼任しません。
- 生存している恋人は「あなただけの情報」で相方の名前を確認できます。ほかの役職や主催者には返しません。
- 片方が処刑・襲撃・途中退場で脱落すると、相方も即座に後追いで脱落します。2人の脱落を処理してから勝敗を判定します。
- 襲撃対象への護衛が成功した場合、2人とも生存します。相方だけを護衛しても後追いは防げません。
- 占い・霊媒は白です。霊媒通知は直接処刑された1人分だけで、後追い・途中退場では追加通知しません。
- 夜は対象選択をせず確認だけ行います。後追い後は確認・投票の対象人数から2人とも除きます。
- 村側勝利で恋人も勝利します。脱落していても勝利点を獲得し、生存点・投票の貢献点は村人と同じ規則です。後追いで夜に脱落した人には、その朝の生存点は付きません。
- 処刑・朝の結果には追加で脱落した人を表示し、役職名は終了まで表示しません。最終画面では直接の脱落者と後追いの脱落者をまとめて表示します。

## 互換性と検証

旧配役にない `lover` は0人として扱います。既存の部屋の配点に `lover: 5` を追加し、再実行で設定済みの点数を上書きしません。新しい画面もSQL未適用時は6役職の設定を送信し、古い設定画面から恋人の配点を省略した場合も現在値を維持します。

自動テスト98件で、配役・相方の閲覧権限・白判定・護衛・処刑・襲撃・途中退場・後追いでの終了・採点・再送・再戦・旧配役を確認しています。実環境と実機での試遊はSQL適用後に行ってください。
