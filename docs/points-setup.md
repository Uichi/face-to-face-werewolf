# 勝利・生存・貢献ポイントを有効にする

## Supabaseでの操作

009（結果の全員確認）まで追加済みのプロジェクトに適用します。

1. `supabase/migrations/202609280010_points.sql` を開き、全文をコピーします。
2. Supabaseの **SQL Editor → New** に貼り付け、**Run** を押します。
3. **Success. No rows returned** と表示されたら、全員がゲーム画面を再読み込みします。
4. 待機室に累計ポイントと採点ルールが表示されます。「今夜のルール → 設定を変更」で役職別の勝利点を変更できます。

部屋や参加者を削除する必要はありません。同じSQLを再実行しても得点は消えません。SQL適用後に開始した試合から採点します。すでに進行中・終了済みの試合は遡って採点せず、次の再戦から対象となります。SQL適用前の画面ではポイント機能を表示せず、従来どおり遊べます。

## 採点ルール

1試合の得点は **勝利点＋生存点＋貢献点** です。

- 勝利点：村人・占い師・霊媒師・騎士は初期5点、人狼・狂人は初期6点。勝った陣営の全員に加点します。主催者が開始前に各役職0〜10点で設定でき、開始時の配点を固定します。
- 生存点：初日を除き、夜の処理後に生存していれば＋1点、最大3点。最終夜も対象です。負けても獲得できます。
- 貢献点：以下の成功ごとに＋1点、合計最大3点。勝った陣営だけが獲得できます。
  - 村側：処刑された人狼へ投票していた。
  - 人狼・狂人：処刑された村側へ投票していた。
  - 占い師：占いで人狼を発見。同じ人狼への再占いは加点なし。
  - 騎士：護衛で襲撃を防いだ。連続護衛も成功ごとに対象。

決選投票があれば最後の投票のみ評価し、処刑なしなら投票による加点はありません。初夜の白通知・霊媒結果の受信・襲撃自体は加点しません。襲撃された占い師の能力も評価します。脱落者はそれまでの実績を維持し、勝利点も通常どおり対象となります。途中退場後に実績は増えません。

試合中の実績は非公開です。結果画面では各自の得点内訳と累計順位を表示します。同点は同順位で、入室順に並びます。投票先や能力の対象は公開しません。

## 累計とリセット

再戦では累計と配点を維持します。待機室で主催者が「全員の累計をリセット」を押して確認すると、全員0点になります。配点設定は変わりません。

再接続では累計を維持します。待機室から退出・削除された人は、再入室で0点になります。新しい部屋へは持ち越しません。部屋の削除に合わせてポイントも削除されます。

## 開発・検証

部屋に `victory_points`、参加者に `points` を追加します。試合の `scoring` は非公開の固定配点・生存数・貢献数・発見済み対象を保持し、終了時の `scores` は集計済み内訳だけを公開します。

`game_command` が既存の部屋ロックを取得し、勝敗確定・累計加算・試合保存を同じトランザクションで実行します。`scores` の存在が確定済みの印となり、再送・読み取りで再加算しません。再戦は試合データのみ削除します。

`lobby_command('settings')` は任意の `victoryPoints` を受け取り、省略時は現在の配点を保持します。`score_command('reset')` は部屋ID・現在のrevisionを受け取り、待機中の主催者のみ許可します。古いrevisionではリセットしません。

自動テスト85件を通過。採点条件・上限・二重送信・再戦・配点・権限・旧試合の互換性・情報非公開を確認しています。Supabase実環境での適用とスマートフォンでの試遊はSQL追加後に確認してください。
