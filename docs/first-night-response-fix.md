# 初夜の最後の確認後、画面が進まない不具合

## 原因
パン配達データがない状態で初日の議論へ移ると、従来の表示判定がSQLのNULLになり、応答全体もNULLになっていました。確認と段階の更新は保存されても、端末が最新状態を受け取れず初夜のままに見えます。

## 適用
`202610300028_thief_reveal.sql` の後に、`202610310029_first_night_response_fix.sql` の全文をSupabase SQL Editorへ貼り付け、Runを押してください。過去のSQLや保存データは削除しません。繰り返し実行できます。

このSQLはパン配達の表示用応答だけを修正します。全員完了による進行、能力、勝敗、得点、秘密情報の権限は変更しません。画面の再公開は不要です。

実行後、止まっている端末でページを再読み込みしてください。既に昼へ進んでいる試合では、現在の段階と残り時間に復帰します。議論時間が経過していれば投票へ進んでいる場合があります。再読み込みで役職や投票を配り直すことはありません。

## 確認
修正前の関数で空の応答を再現。修正後は5人・8人・13人で、初夜最後の確認、同一操作の再送、全員の状態再取得を検証。パンあり・なし、旧データの未設定、初夜・通常の朝、再適用時のデータ保持と関数の権限も検証。
