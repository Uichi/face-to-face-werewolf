# ゲーム機能を有効にする

部屋への参加ができる既存のSupabaseプロジェクトに、一度だけゲーム用の処理を追加します。

1. `supabase/migrations/202609270003_game.sql` を開き、全文をコピーします。
2. Supabaseの「SQL Editor」で「New」を選び、空の編集欄へ貼り付けます。
3. 「Run」を押します。「Success. No rows returned」と表示されれば完了です。
4. 公開ページを全員の端末で再読み込みします。5人以上の待機室で、主催者が「ゲームを開始する」を押します。

以前の部屋作成用SQLをもう一度実行する必要はありません。この追加SQLは既存の部屋を削除せず、再実行も可能です。エラーが出たら、その文章を確認してから先に進みます。

## 最初の試遊

- 各端末で役職を表示して「役職を確認しました」を押します。
- 初夜は全員の確認後に昼へ進みます。占い師の白通知は本人だけが確認できます。
- 議論終了後、対象を選び、確定します。確定後は変更できません。
- 処刑・朝の結果は、生存者全員が「結果を確認しました」を押すと進みます。既存環境は [結果確認の更新](result-confirmation-setup.md) を適用してください。
- 夜は全員が自分の情報を開き、能力の対象選択・確定、または夜の確認を行います。生存者全員の完了で、残り時間に関係なく朝へ進みます。
- 復帰できない人は、主催者の操作から脱落扱いにできます。
- 試合終了後は役職が公開され、主催者が再戦を選べます。

## 実装・検証範囲

`game_command` は認証された参加者だけが呼べます。配役・判定・タイマーはサーバー時刻で確定し、本人用・生存人狼用・公開用の情報を分けて返します。部屋単位のロックで同時更新を直列化し、操作IDと試合・段階IDで再送や古い操作を検証します。

画面は更新通知に加えて2秒ごとに最新状態を取得します。時間経過は取得・操作時に処理されるので、全員が閉じている間は次の接続時に進みます。通知には秘密情報を含めません。脱落者は公開情報だけを取得します。

ローカルでは実際のSQLをPGliteで実行し、5・8・10人の終了・再戦、権限制限、二重送信、途中脱落を検証しています。Supabase実環境とスマホ実機の確認は、この設定追加後に行います。24時間清掃の定期実行は `supabase-setup.md` の手順で別途設定します。
