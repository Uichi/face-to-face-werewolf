# ゲーム進行の実装

`src/domain/game.ts` はサーバー用の状態遷移処理です。通信・データベース・画面から独立して動作します。

## 操作と段階

|段階|受け付ける参加者操作|次へ進む条件|
|---|---|---|
|roles|確認|生存者全員の確認|
|firstNight|確認|生存者全員の確認、待ち時間なし|
|discussion|主催者による早期投票・延長|時間終了または早期投票|
|vote / runoff|対象選択・確定、主催者の延長|全生存者の確定|
|execution|主催者の次へ|通常の夜へ|
|night|能力者の選択・確定、他の生存者の確認、主催者の延長|全生存者完了かつ時間終了|
|morning|主催者の次へ|翌日の議論へ|
|finished|なし|結果表示のみ|

主催者の途中脱落操作は終了前の全段階で受け付けます。脱落した主催者も管理操作を行えます。自己投票・自己能力使用・死者による参加操作は拒否します。

仕様の細部として、議論延長も60秒単位、上限なしとしました。役職確認中の途中脱落では、残った生存者の確認のみを待ちます。議論・結果表示中の途中脱落では、勝敗判定と脱落者一覧の更新を行い、元の段階・残り時間を保持します。画面での確認ダイアログは今後実装します。

## サーバー接続時の契約

- `createGame` は新しい試合IDで呼び、全役職をサーバーで配布します。
- `applyCommand` は元の状態を変更せず、新しい状態を返します。失敗時は保存しません。
- 試合ID・段階ID・操作IDを毎回渡します。再試行は同じ操作ID・同じ内容を使います。
- 同じ操作の再送は状態を変えません。同じIDで異なる内容、古い段階、新旧の異なる試合は拒否します。
- 認証済みの参加者IDをサーバーが設定します。リクエスト本文のactorIdを信用してはいけません。
- 時刻と乱数はサーバーから渡します。乱数は暗号学的に安全な等確率の整数生成器を使用します。
- サーバー時計の通知はactorId=nullのtickです。ブラウザにtickを直接許可してはいけません。定期処理と再接続時の期限確認が必要です。
- 同時操作を安全に処理するには、データベースのトランザクションまたはバージョン照合による更新が必須です。純粋な進行関数だけでは同時更新を保護しません。
- 外部入力の形・長さ・操作種別はAPI入口で検証し、回数制限を設けます。
- 接続検出、主催権限の移行、再戦の待機室、24時間削除は接続層の開発時に実装します。

## 情報の配信

クライアントには`viewFor`の結果だけを渡します。Game本体、確定者一覧、票の対応、操作履歴を公開配信・ログに載せないでください。

- 公開情報: 段階・期限・人数・公開集計・犠牲者・主催者による途中脱落一覧。
- 本人情報: 生存者だけの役職・自分の選択と確定状況・能力結果。
- 人狼情報: 生存人狼だけが仲間と通常の夜の選択状況を取得可能。
- 脱落者: 公開情報のみ。夜に死亡した占い師の結果は内部状態には成立するが、脱落後の画面には送信しない。
- 終了後: 全役職を公開し、個別投票・夜行動・能力結果は公開しない。

これらの分離は関数のテストで検証済みですが、Supabaseの閲覧制限・API・リアルタイム配信を使った情報漏えい試験はまだです。
